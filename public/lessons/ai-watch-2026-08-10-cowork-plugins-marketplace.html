Plugins as the new unit of AI tooling: inside Cowork's marketplace

A plugin bundles a skill, a slash command, and an MCP connector into one install. That packaging choice says a lot about where "AI tools" are heading in 2026.

Contents

  2. Anatomy of a plugin
  3. Why bundle skills, commands, and connectors together
  4. The marketplace model: official and custom
  5. Why this matters beyond Cowork

1. What's actually new

Cowork mode — the desktop feature for non-developers to automate file and task work — now supports installable plugins: packaged bundles that add domain-specific skills, slash commands, and connectors (MCP servers wired to external tools) to a session in one step. Anthropic runs an official marketplace of curated plugins, and any publisher can stand up a custom marketplace by hosting a manifest file at a public URL — the same open model GitHub used for package registries.

One example: the "Claude Design" plugin from Anthropic Labs turns Cowork into a text-to-prototype tool for decks, landing pages, and one-pagers, exporting to PDF, PPTX, Canva, or HTML, and handing off polished output to Claude Code for implementation.

2. Anatomy of a plugin

ComponentWhat it does
SkillDomain expertise and step-by-step workflows that activate automatically when relevant — the model reaches for it without being explicitly told to.
Slash commandAn explicit action the user triggers by name (e.g. /deploy), rather than something the model decides to use on its own.
ConnectorAn MCP server wired to a real external tool (Slack, Notion, a CRM) so the plugin can read and act on live data, not just answer from static instructions.

Individually, skills, commands, and connectors already existed as separate concepts. Wrapping all three into a single installable unit is the actual product decision here — it turns "configure an agent for a workflow" into "click install."

3. Why bundle skills, commands, and connectors together

A skill without a connector is just instructions with no access to real data. A connector without a skill is a raw API with no judgment about when and how to use it well. Most useful automations need both plus, often, an explicit trigger a user can invoke directly. Shipping the three together means an install gives you a working capability instead of three separate configuration steps that have to be wired up correctly by hand.

The parallel worth noticing: this mirrors how browser extensions bundled UI, permissions, and background scripts into one install two decades ago, and how VS Code extensions bundle language servers, commands, and UI panels today. Packaging capability as one unit — rather than as separate configuration the user assembles — is a recurring pattern whenever a platform's ecosystem starts to mature.

4. The marketplace model: official and custom

The official marketplace covers categories like productivity, legal, sales, financial services, HR, and engineering, curated and vetted by Anthropic. But the distribution model is deliberately open: anyone can publish a marketplace by exposing a manifest at a URL, the same decentralized approach used for most modern package ecosystems (npm registries, VS Code marketplaces, browser extension stores under custom review).

Anthropic also publishes an open source repository of plugins aimed specifically at knowledge workers, separate from the built-in marketplace — a signal that the intent is a broader ecosystem, not a single closed catalog.

5. Why this matters beyond Cowork

Plugin support is currently a research preview for paid Claude users, which means the format is still being iterated on — but the direction is clear: the unit of "an AI tool" is shifting away from a single prompt or a single connector, toward a packaged bundle that combines judgment (skill), an explicit trigger (command), and live access (connector). Anyone evaluating or building on top of Claude's tooling ecosystem should expect "plugin" to become the default shape new capabilities ship in, rather than a one-off skill or an isolated MCP server.

Plugins como a nova unidade de ferramentas de IA: por dentro do marketplace do Cowork

Um plugin junta uma skill, um comando de barra e um conector MCP numa instalação só. Essa escolha de empacotamento diz bastante sobre pra onde as "ferramentas de IA" estão indo em 2026.

1. O que de fato é novo

O Cowork — o recurso de desktop pra pessoas não-desenvolvedoras automatizarem trabalho com arquivos e tarefas — agora suporta plugins instaláveis: pacotes que adicionam skills específicas de domínio, comandos de barra e conectores (servidores MCP ligados a ferramentas externas) numa sessão de um passo só. A Anthropic mantém um marketplace oficial de plugins curados, e qualquer publicador pode montar um marketplace customizado hospedando um arquivo de manifesto numa URL pública — o mesmo modelo aberto que o GitHub usou pra registros de pacotes.

Um exemplo: o plugin "Claude Design", da Anthropic Labs, transforma o Cowork numa ferramenta de texto-pra-prototipo pra decks, landing pages e one-pagers, exportando pra PDF, PPTX, Canva ou HTML, e entregando o resultado polido pro Claude Code implementar.

2. Anatomia de um plugin

ComponenteO que faz
SkillConhecimento de domínio e fluxos passo a passo que ativam automaticamente quando relevantes — o modelo recorre a ela sem precisar de instrução explícita.
Comando de barraUma ação explícita que o usuário aciona pelo nome (ex: /deploy), em vez de algo que o modelo decide usar por conta própria.
ConectorUm servidor MCP ligado a uma ferramenta externa real (Slack, Notion, um CRM) pra que o plugin possa ler e agir sobre dados ao vivo, não só responder com base em instruções estáticas.

Individualmente, skills, comandos e conectores já existiam como conceitos separados. Envolver os três numa unidade instalável só é a decisão de produto real aqui — transforma "configurar um agente pra um fluxo de trabalho" em "clicar em instalar".

3. Por que juntar skills, comandos e conectores

Uma skill sem conector é só instrução sem acesso a dado real. Um conector sem skill é uma API crua sem discernimento de quando e como usar bem. A maioria das automações úteis precisa dos dois, mais, com frequência, um gatilho explícito que o usuário pode acionar direto. Entregar os três juntos faz com que uma instalação já dê uma capacidade funcionando, em vez de três passos de configuração separados que precisam ser conectados corretamente na mão.

O paralelo que vale notar: isso espelha como extensões de navegador juntavam interface, permissões e scripts em background numa instalação só, duas décadas atrás, e como extensões do VS Code juntam language servers, comandos e painéis de UI hoje. Empacotar capacidade como uma unidade — em vez de configuração separada que o usuário monta — é um padrão recorrente sempre que o ecossistema de uma plataforma começa a maturar.

4. O modelo de marketplace: oficial e customizado

O marketplace oficial cobre categorias como produtividade, jurídico, vendas, serviços financeiros, RH e engenharia, curadas e verificadas pela Anthropic. Mas o modelo de distribuição é deliberadamente aberto: qualquer pessoa pode publicar um marketplace expondo um manifesto numa URL, a mesma abordagem descentralizada usada pela maioria dos ecossistemas de pacotes modernos (registros npm, marketplaces do VS Code, lojas de extensão de navegador sob revisão própria).

A Anthropic também publica um repositório open source de plugins voltado especificamente a trabalhadores de conhecimento, separado do marketplace embutido — um sinal de que a intenção é um ecossistema mais amplo, não um catálogo único e fechado.

5. Por que isso importa além do Cowork

O suporte a plugins hoje é uma pré-visualização de pesquisa pra usuários pagos do Claude, o que significa que o formato ainda está sendo iterado — mas a direção é clara: a unidade de "uma ferramenta de IA" está migrando de um prompt único ou um conector isolado, pra um pacote combinando discernimento (skill), um gatilho explícito (comando) e acesso ao vivo (conector). Quem está avaliando ou construindo em cima do ecossistema de ferramentas do Claude deveria esperar que "plugin" se torne o formato padrão em que novas capacidades chegam, em vez de uma skill isolada ou um servidor MCP solto.
