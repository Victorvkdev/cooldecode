Who spent the tokens? Claude's new Usage and Cost Analytics API and pooled budgets

Between October 28 and 29, Anthropic shipped three things that all answer the same question: where is our Claude spend going, and who should be allowed to use more of it? An API for the numbers, reports for the story behind them, and shared budgets for the guardrails.

1. Why this matters

Last lesson's point was that the price per token is not the bill. The natural next question is how you find out what the bill actually is, per model, per project and per person. Until a team can see that, "cost per task" stays a guess. These releases are Anthropic's answer for organizations: the raw data (API), the interpretation (reports) and the control (budgets).

Two different audiences. The API is for Claude Console and Claude Enterprise organizations and is something an engineer wires into a dashboard. Smart reports, surveys and pooled budgets are Claude Enterprise features that admins use from the product. If you use Claude personally, none of this changes your day, but it shows how teams are expected to manage AI spend.

2. The Usage and Cost Analytics API (Oct 29)

According to the Claude Developer Platform release notes of October 29, 2026, this is a new beta API that reports token usage and cost for Console and Enterprise organizations. Two endpoints:

GET /v1/organizations/analytics/usage
GET /v1/organizations/analytics/cost

# beta header required:
anthropic-beta: analytics-usage-cost-2026-08-24

Results can be filtered and grouped by dimensions such as model, workspace, API key, and the user or service account behind each request. That last dimension is the new useful one: you can attribute spend to a person or a service, not only to a key.

What it replaces

The older Usage and Cost API is now legacy, and so are four Enterprise Analytics API endpoints: usage_report, cost_report, user_usage_report and user_cost_report. They all remain supported, and Anthropic published migration guides. Practical reading: nothing breaks today, but new integrations should start on the new endpoints.

3. Smart reports and in-app surveys (Oct 28)

Numbers tell you how much; the October 28 Enterprise announcement tries to tell you why. It made three features generally available.

  • Smart reports. Pick a team, a date range and products. Claude analyzes a sample of that team's transcripts, groups the work into workstreams, and shows spend per workstream, deliverables, and common friction (for example a missing connector or a failed tool call). Each report ends with a consolidated list of recommendations, such as recurring workflows worth turning into skills, or rules to add to a code repository. Anthropic states they are not meant for evaluating individual performance or for employment decisions.
  • In-app surveys. A short card after a reply, with default questions about value: the most valuable thing done recently, how Claude changed the time it took, what a teammate should copy, and what would break or slow down first if access vanished. Admins can edit questions, audience and timing, and export responses to a spreadsheet.
  • Pooled group budgets. Covered next.

4. Pooled group budgets, and a simulator

Instead of a fixed allowance per person, a group gets one shared monthly budget. The motivation: heavy users no longer hit an individual limit early in the month while teammates leave budget unused. Two rules matter:

  1. Every request counts against both the group budget and the member's own limit, and a member stops at whichever runs out first. Member limits stay as a guardrail against unusually high individual use.
  2. Admins with billing permissions get email alerts at 50%, 75%, 95% and 100% of the budget. Someone who hits a limit can request more from inside Claude, and the request goes to admins for review. The setup suggests an amount based on the group's recent usage.

Try it. This is a simplified model of the rules above, not Anthropic's implementation.

5. Putting it together

  1. Measure. Pull usage and cost grouped by model and workspace; this gives you real tokens per task for the cost-per-task comparison from the last lesson.
  2. Understand. Use reports or your own review to find which workstreams are expensive and which are valuable (they are not always the same).
  3. Control. Set a pooled budget with alert thresholds, keep per-member limits as a safety net.
  4. Re-check. New models and prices land every few weeks, so repeat the loop.
Takeaway: AI spend is becoming an operations topic with the same tooling as cloud spend: an analytics API, per-team views and shared budgets with alerts. The habit worth building is attributing cost to a project or person from day one, because retrofitting it later is painful.

IA Watch · Novidades da Anthropic

Quem gastou os tokens? A nova API de Uso e Custo do Claude e os orçamentos compartilhados

Entre 28 e 29 de outubro, a Anthropic lançou três coisas que respondem à mesma pergunta: para onde está indo o gasto com Claude, e quem deve poder usar mais dele? Uma API para os números, relatórios para a história por trás deles e orçamentos compartilhados como proteção.

1. Por que isso importa

O ponto da lição anterior foi que o preço por token não é a fatura. A pergunta seguinte é como descobrir qual é a fatura de verdade, por modelo, por projeto e por pessoa. Enquanto um time não enxerga isso, "custo por tarefa" é chute. Esses lançamentos são a resposta da Anthropic para organizações: os dados brutos (API), a interpretação (relatórios) e o controle (orçamentos).

Dois públicos diferentes. A API é para organizações do Claude Console e do Claude Enterprise e é algo que um engenheiro liga a um painel. Relatórios inteligentes, pesquisas e orçamentos compartilhados são recursos do Claude Enterprise que admins usam dentro do produto. Se você usa o Claude de forma pessoal, nada muda no seu dia, mas mostra como times devem gerenciar gasto com IA.

2. A API de Uso e Custo (29/10)

Segundo as release notes da Claude Developer Platform de 29/10/2026, é uma API nova em beta que reporta uso de tokens e custo de organizações do Console e do Enterprise. Dois endpoints:

GET /v1/organizations/analytics/usage
GET /v1/organizations/analytics/cost

# header beta obrigatório:
anthropic-beta: analytics-usage-cost-2026-08-24

Os resultados podem ser filtrados e agrupados por dimensões como modelo, workspace, chave de API e o usuário ou conta de serviço por trás de cada requisição. Essa última dimensão é a nova e útil: dá para atribuir o gasto a uma pessoa ou a um serviço, não só a uma chave.

O que ela substitui

A API de Uso e Custo antiga agora é legada, e também quatro endpoints da Enterprise Analytics API: usage_report, cost_report, user_usage_report e user_cost_report. Todos continuam suportados, e a Anthropic publicou guias de migração. Leitura prática: nada quebra hoje, mas integrações novas devem começar pelos endpoints novos.

3. Relatórios inteligentes e pesquisas no app (28/10)

Números dizem quanto; o anúncio de 28/10 para o Enterprise tenta dizer por quê. Três recursos ficaram disponíveis para todos.

  • Relatórios inteligentes. Escolha um time, um período e os produtos. O Claude analisa uma amostra das transcrições do time, agrupa o trabalho em frentes, e mostra gasto por frente, entregas e pontos de atrito comuns (por exemplo um conector faltando ou uma chamada de ferramenta que falhou). Cada relatório termina com uma lista consolidada de recomendações, como fluxos recorrentes que valem virar skills, ou regras para adicionar a um repositório de código. A Anthropic afirma que não servem para avaliar desempenho individual nem para decisões de emprego.
  • Pesquisas no app. Um cartão curto depois de uma resposta, com perguntas padrão sobre valor: a coisa mais valiosa feita recentemente, como o Claude mudou o tempo gasto, o que um colega deveria copiar, e o que quebraria ou ficaria mais lento primeiro se o acesso sumisse. Admins editam perguntas, público e momento, e exportam as respostas para planilha.
  • Orçamentos compartilhados por grupo. Veja a seguir.

4. Orçamentos compartilhados por grupo, e um simulador

Em vez de uma cota fixa por pessoa, o grupo recebe um orçamento mensal compartilhado. A motivação: quem usa muito não bate num limite individual no começo do mês enquanto colegas deixam orçamento sobrando. Duas regras importam:

  1. Toda requisição conta nos dois, no orçamento do grupo e no limite do próprio membro, e o membro para no que acabar primeiro. Os limites por membro continuam como proteção contra uso individual anormalmente alto.
  2. Admins com permissão de cobrança recebem alertas por e-mail a 50%, 75%, 95% e 100% do orçamento. Quem bate num limite pode pedir mais de dentro do Claude, e o pedido vai para revisão dos admins. A configuração sugere um valor com base no uso recente do grupo.

Teste. É um modelo simplificado das regras acima, não a implementação da Anthropic.

5. Juntando tudo

  1. Meça. Puxe uso e custo agrupados por modelo e workspace; isso dá tokens reais por tarefa para a comparação de custo por tarefa da lição anterior.
  2. Entenda. Use relatórios ou sua própria revisão para achar quais frentes são caras e quais são valiosas (nem sempre são as mesmas).
  3. Controle. Defina um orçamento compartilhado com alertas e mantenha limites por membro como rede de segurança.
  4. Reveja. Modelos e preços novos saem a cada poucas semanas, então repita o ciclo.
Conclusão: gasto com IA está virando assunto de operações, com as mesmas ferramentas do gasto em nuvem: API de análise, visões por time e orçamentos compartilhados com alertas. O hábito que vale construir é atribuir custo a um projeto ou pessoa desde o primeiro dia, porque adaptar depois dói.
