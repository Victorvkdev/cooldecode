Anthropic built the shopping brain, and skipped the wallet

Anthropic just open-sourced Claude Commerce Agents: a free, Apache-2.0 blueprint for building AI shopping assistants and merchant-operations agents on Claude — with zero payment logic built in. That gap isn't an oversight; it's the whole strategy. Here's what the blueprint actually contains and why Anthropic left the hardest, most regulated part of e-commerce to everyone else.

1. What Claude Commerce Agents actually is

On September 2, 2026, Anthropic released Claude Commerce Agents, a reference implementation — not a hosted product — showing how to build agents that shop on a customer's behalf and agents that run the operational side of a merchant's business, both powered by Claude. The whole thing is released under an Apache 2.0 license, meaning anyone can take the code, modify it, and ship it commercially without paying Anthropic anything beyond normal API usage.

Technically, it's a Python 3.11+ and Node 22 codebase that runs locally with just an ANTHROPIC_API_KEY, and because it's built against the standard Anthropic client, the same code can run against the Claude API directly, or through Amazon Bedrock, Google Cloud Vertex AI, or Microsoft Foundry without changes. That "runs anywhere Claude runs" design is consistent with how Anthropic has shipped most of its recent agent tooling — MCP servers, Skills, Files API — as open specifications rather than closed platforms.

2. Two agents, four industries

The blueprint ships two distinct agent roles, which map to the two sides of any storefront:

AgentJob
Shopper agentHelps a customer search a catalog, compare options, build a cart, and walk through checkout — the AI equivalent of a knowledgeable in-store sales associate.
Merchant agentHandles the operational back end: catalog search, inventory questions, sales-ops tasks — things a merchant's own staff would otherwise do manually.

Both agents come with four runnable reference verticals — retail, travel, telecom, and entertainment/ticketing — so a developer isn't starting from an empty prompt; they're starting from a working demo tuned to a specific industry's product catalog shape and conversational patterns.

Anthropic's own reported numbers claim carts built with the shopper agent run up to 35% larger, and shoppers using it are 60% more likely to complete a purchase compared to a traditional search-and-filter flow — numbers worth treating as a vendor's best-case pitch rather than an independently verified benchmark, but directionally consistent with what other conversational-commerce experiments have reported.

3. Why Anthropic skipped payments on purpose

The most telling design decision in the whole blueprint is what's not there: no payment protocol, no checkout processor, no ad layer. Anthropic built the reasoning and conversation layer — the "brain" that decides what to search for, what to recommend, when to add something to a cart — and left the actual movement of money to established players. The blueprint's docs point explicitly to partners like Visa and Mastercard for that piece.

This is a deliberate scope cut, not a missing feature. Payments sit inside one of the most heavily regulated, liability-sensitive parts of any commerce stack — fraud rules, chargeback handling, PCI compliance, region-specific financial regulation. By staying out of that layer entirely, Anthropic avoids becoming a financial intermediary (and the compliance burden that comes with it) while still owning the part of the stack that's hardest to replicate: the agent's judgment.

4. Why a "blueprint" instead of a product

Anthropic has increasingly favored this "open reference implementation" pattern over shipping a finished, hosted product — the same approach it used for MCP itself and for Agent Skills. The advantages of a blueprint over a walled-garden product are straightforward: retailers and platforms can adapt the code to their exact catalog, brand voice, and existing checkout stack instead of retrofitting their business around someone else's API; and because it's Apache 2.0, competitors and partners (Shopify, for instance, has been named alongside this release) can build commercial products on top of it without asking Anthropic for permission.

The tradeoff is that Anthropic doesn't capture the commerce transaction itself — only the underlying model calls the agents make along the way. That's consistent with Anthropic's broader platform bet: win by being the reasoning layer under as many agent categories as possible, rather than by owning any single vertical product.

5. Where this fits in the wider agentic-commerce race

Commerce is one of the most contested fronts in the current wave of AI agent tooling — every major model provider has been racing to define how AI assistants shop, recommend, and eventually transact on a user's behalf, and standards for agent-initiated payments are still being sorted out industry-wide. Anthropic's move here is notable less for being first and more for how narrowly it scopes Claude's role: reasoning and conversation, full stop, with payments treated as someone else's problem to solve on top.

That narrow scoping is a pattern worth watching across Anthropic's tool releases generally — MCP standardized how agents connect to external tools and data, Skills standardized how agents package reusable capabilities, and now Commerce Agents standardizes how a shopping conversation should be structured, in each case leaving the messiest, most regulated adjacent layer (hosting infrastructure, distribution, payments) to the existing ecosystem.

6. What this means if you build software

If you build anything customer-facing with a product catalog — retail, travel booking, ticketing, telecom plans — this blueprint is a legitimate starting point to prototype a conversational shopping flow instead of writing agent orchestration logic from scratch.
If you're evaluating vendor performance claims (the "35% larger carts, 60% more conversions" kind), treat them the way you'd treat any vendor-published benchmark: real signal about the direction of the effect, but not a number you should expect to reproduce exactly without your own A/B test.

The bigger pattern to take away: when a model provider ships something free and open under a permissive license, look at what's deliberately missing as much as what's included. Here, the missing piece — payments — tells you exactly where Anthropic thinks the real risk (and the real competitive moat of others) still lives.

1. O que é o Claude Commerce Agents, de fato

Em 2 de setembro de 2026, a Anthropic lançou o Claude Commerce Agents, uma implementação de referência — não um produto hospedado — mostrando como construir agentes que compram em nome de um cliente e agentes que rodam o lado operacional do negócio de um lojista, ambos rodando sobre o Claude. Tudo isso sob licença Apache 2.0, o que significa que qualquer um pode pegar o código, modificar e lançar comercialmente sem pagar nada à Anthropic além do uso normal de API.

Tecnicamente, é uma base de código em Python 3.11+ e Node 22 que roda localmente só com uma ANTHROPIC_API_KEY, e como é construída em cima do cliente padrão da Anthropic, o mesmo código roda direto na API do Claude, ou via Amazon Bedrock, Google Cloud Vertex AI ou Microsoft Foundry, sem mudanças. Esse design "roda em qualquer lugar que o Claude rode" é consistente com como a Anthropic vem lançando a maior parte do seu ferramental recente de agentes — servidores MCP, Skills, Files API — como especificações abertas em vez de plataformas fechadas.

2. Dois agentes, quatro setores

O blueprint traz dois papéis de agente distintos, que mapeiam os dois lados de qualquer loja:

AgenteFunção
Agente de compra (shopper)Ajuda um cliente a buscar no catálogo, comparar opções, montar um carrinho e passar pelo checkout — o equivalente em IA a um vendedor de loja física bem informado.
Agente de lojista (merchant)Cuida do backend operacional: busca de catálogo, questões de estoque, tarefas de operações de venda — coisas que a própria equipe do lojista faria manualmente.

Os dois agentes vêm com quatro verticais de referência prontas pra rodar — varejo, viagens, telecom e entretenimento/ingressos — então quem for desenvolver não começa de um prompt vazio; começa de uma demo funcional já ajustada ao formato de catálogo de produto e aos padrões de conversa de cada setor.

Os números divulgados pela própria Anthropic dizem que carrinhos montados com o agente de compra ficam até 35% maiores, e compradores usando ele têm 60% mais chance de concluir a compra em comparação a um fluxo tradicional de busca e filtro — números que vale tratar como o melhor cenário de um discurso de vendedor, não como um benchmark verificado de forma independente, mas na direção condizente com o que outros experimentos de comércio conversacional já relataram.

3. Por que a Anthropic deixou pagamentos de fora de propósito

A decisão de design mais reveladora de todo o blueprint é o que não está lá: nenhum protocolo de pagamento, nenhum processador de checkout, nenhuma camada de anúncios. A Anthropic construiu a camada de raciocínio e conversa — o "cérebro" que decide o que buscar, o que recomendar, quando adicionar algo ao carrinho — e deixou a movimentação de dinheiro em si pra players já estabelecidos. A documentação do blueprint aponta explicitamente pra parceiros como Visa e Mastercard pra essa parte.

Esse é um corte de escopo deliberado, não uma funcionalidade faltando. Pagamentos ficam numa das partes mais reguladas e sensíveis a responsabilidade legal de qualquer stack de comércio — regras antifraude, tratamento de chargeback, compliance PCI, regulação financeira específica de cada região. Ao ficar completamente fora dessa camada, a Anthropic evita virar um intermediário financeiro (e o peso de compliance que vem junto) enquanto continua dona da parte do stack mais difícil de replicar: o julgamento do agente.

4. Por que um "blueprint" em vez de um produto

A Anthropic vem preferindo cada vez mais esse padrão de "implementação de referência aberta" em vez de lançar um produto hospedado e fechado — a mesma abordagem que usou pro próprio MCP e pros Agent Skills. As vantagens de um blueprint sobre um produto de jardim murado são diretas: lojistas e plataformas podem adaptar o código exatamente ao catálogo, à voz de marca e ao stack de checkout que já têm, em vez de reformular o negócio em volta da API de outra empresa; e por ser Apache 2.0, concorrentes e parceiros (a Shopify, por exemplo, foi citada junto com esse lançamento) podem construir produtos comerciais em cima sem pedir permissão à Anthropic.

A contrapartida é que a Anthropic não captura a transação de comércio em si — só as chamadas de modelo que os agentes fazem no caminho. Isso é consistente com a aposta de plataforma mais ampla da Anthropic: vencer sendo a camada de raciocínio por baixo do maior número possível de categorias de agente, em vez de ser dona de um produto vertical específico.

5. Onde isso se encaixa na corrida mais ampla de comércio agêntico

Comércio é uma das frentes mais disputadas da onda atual de ferramental de agentes de IA — todo grande provedor de modelo vem correndo pra definir como assistentes de IA compram, recomendam e eventualmente transacionam em nome de um usuário, e os padrões pra pagamentos iniciados por agente ainda estão sendo definidos pelo setor inteiro. O movimento da Anthropic aqui chama atenção menos por ser o primeiro e mais por quão estreito é o escopo que ela dá ao papel do Claude: raciocínio e conversa, ponto final, com pagamento tratado como problema de outra empresa resolver em cima.

Esse escopo estreito é um padrão que vale acompanhar nos lançamentos de ferramentas da Anthropic de forma geral — o MCP padronizou como agentes se conectam a ferramentas e dados externos, os Skills padronizaram como agentes empacotam capacidades reutilizáveis, e agora o Commerce Agents padroniza como uma conversa de compra deveria ser estruturada, em cada caso deixando a camada adjacente mais confusa e regulada (infraestrutura de hospedagem, distribuição, pagamentos) pro ecossistema já existente.

6. O que isso significa se você constrói software

Se você constrói algo voltado a cliente com catálogo de produto — varejo, reserva de viagem, ingressos, planos de telecom — esse blueprint é um ponto de partida legítimo pra prototipar um fluxo de compra conversacional em vez de escrever lógica de orquestração de agente do zero.
Se você está avaliando números de performance divulgados por fornecedor (o tipo "carrinhos 35% maiores, 60% mais conversão"), trate como trataria qualquer benchmark publicado por fornecedor: sinal real da direção do efeito, mas não um número que você deveria esperar reproduzir exatamente sem o seu próprio teste A/B.

O padrão maior pra guardar: quando um provedor de modelo lança algo grátis e aberto sob licença permissiva, olhe pro que está deliberadamente faltando tanto quanto pro que está incluído. Aqui, a peça que falta — pagamentos — diz exatamente onde a Anthropic acha que o risco real (e o fosso competitivo real de outras empresas) ainda mora.
