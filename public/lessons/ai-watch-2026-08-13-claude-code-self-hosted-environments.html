Claude Code can now run on your own servers — but your prompts still go to Anthropic

Anthropic just opened a public beta letting Team and Enterprise customers run Claude Code sessions inside their own network. Here's what that actually changes, and what it doesn't.

Contents
  1. What was announced
  2. Why this exists
  3. What it is NOT
  4. Trade-offs
  5. Why a solo learner should care

1. What was announced

Anthropic opened a public beta for self-hosted environments in Claude Code — its coding agent. Instead of a session's file access and command execution happening on Anthropic-managed infrastructure, teams on the Team and Enterprise plans can now run those sessions on servers inside their own network, whether the session was started from the CLI, web, mobile, or desktop.

Concretely, this means a Claude Code session running self-hosted can reach internal services, private databases, and internal package registries that were never exposed to the public internet, and can use compilers, SDKs, and internal command-line tools pre-installed on that infrastructure — none of which a purely Anthropic-hosted session could touch.

2. Why this exists

Coding agents are only as useful as what they can reach. A lot of real engineering work touches things that live behind a firewall on purpose — internal APIs, staging databases, proprietary build tooling, private artifact registries. Until now, using an agent against that kind of environment meant either exposing internal systems to the internet (a security team's nightmare) or keeping the agent's usefulness capped to whatever's public. Self-hosted environments remove that trade-off for organizations that are willing to own the infrastructure.

3. What it is NOT

This is self-hosted execution, not self-hosted inference. The model itself still runs on Anthropic's servers. Prompts, model responses, tool call results, and full session transcripts still travel to Anthropic to generate each response — only the environment where commands actually execute (reading files, running builds, hitting internal services) moves onto the customer's own infrastructure.

It's also off by default, and not available at all for organizations that use Zero Data Retention (ZDR) agreements, since the self-hosted runner needs to persist some session state that ZDR configurations are designed to avoid.

4. Trade-offs

GainCost
Access to internal services/databases without exposing them publiclyEngineering time to set up and maintain the self-hosted runner
Pre-installed internal tooling, compilers, SDKs available to the agentStill not full data isolation — prompts/transcripts still reach Anthropic
Compliance-friendlier network posture for regulated environmentsOnly available on Team/Enterprise plans, and disabled for ZDR customers

5. Why a solo learner should care

Even outside a big team, this is a useful data point about how AI coding tools are evolving: the trend isn't just "make the model smarter", it's "give the agent safer, more controlled ways to reach the real systems a developer actually works with" — internal networks, private repos, custom toolchains. The distinction between "where code executes" and "where the model runs" is also a good mental model to keep in general when evaluating any AI dev tool's privacy claims: always ask which side of that line a given feature is actually solving.

Claude Code agora roda nos seus próprios servidores — mas seus prompts continuam indo pra Anthropic

A Anthropic acabou de abrir uma beta pública deixando clientes Team e Enterprise rodarem sessões do Claude Code dentro da própria rede. Aqui está o que isso muda de verdade, e o que não muda.

Sumário
  1. O que foi anunciado
  2. Por que isso existe
  3. O que isso NÃO é
  4. Trade-offs
  5. Por que isso importa pra quem estuda sozinho

1. O que foi anunciado

A Anthropic abriu uma beta pública de ambientes self-hosted no Claude Code — seu agente de código. Em vez do acesso a arquivos e execução de comandos de uma sessão acontecerem em infraestrutura gerenciada pela Anthropic, times nos planos Team e Enterprise agora podem rodar essas sessões em servidores dentro da própria rede, seja a sessão iniciada pelo CLI, web, mobile ou desktop.

Na prática, isso significa que uma sessão do Claude Code rodando self-hosted consegue acessar serviços internos, bancos de dados privados e registries internos de pacotes que nunca foram expostos à internet pública, e pode usar compiladores, SDKs e ferramentas internas de linha de comando pré-instaladas nessa infraestrutura — nada disso uma sessão puramente hospedada pela Anthropic conseguiria tocar.

2. Por que isso existe

Agentes de código só são tão úteis quanto aquilo que conseguem alcançar. Boa parte do trabalho real de engenharia toca coisas que ficam atrás de um firewall de propósito — APIs internas, bancos de staging, ferramental de build proprietário, registries privados de artefatos. Até agora, usar um agente contra esse tipo de ambiente significava ou expor sistemas internos à internet (um pesadelo pro time de segurança) ou manter a utilidade do agente limitada ao que é público. Ambientes self-hosted removem esse trade-off pras organizações dispostas a assumir a infraestrutura.

3. O que isso NÃO é

Isso é execução self-hosted, não inferência self-hosted. O modelo em si continua rodando nos servidores da Anthropic. Prompts, respostas do modelo, resultados de chamadas de ferramenta e transcrições completas da sessão continuam viajando até a Anthropic pra gerar cada resposta — só o ambiente onde os comandos realmente executam (ler arquivos, rodar builds, acessar serviços internos) se move pra infraestrutura do cliente.

Também vem desligado por padrão, e não está disponível pra organizações que usam acordos de Zero Data Retention (ZDR), já que o runner self-hosted precisa persistir algum estado de sessão que configurações ZDR são desenhadas justamente pra evitar.

4. Trade-offs

GanhoCusto
Acesso a serviços/bancos internos sem expô-los publicamenteTempo de engenharia pra montar e manter o runner self-hosted
Ferramental interno, compiladores e SDKs pré-instalados disponíveis pro agenteAinda não é isolamento total de dados — prompts/transcrições continuam chegando na Anthropic
Postura de rede mais amigável a compliance em ambientes reguladosSó disponível nos planos Team/Enterprise, e desabilitado pra clientes ZDR

5. Por que isso importa pra quem estuda sozinho

Mesmo fora de um time grande, esse é um dado útil sobre como as ferramentas de código com IA estão evoluindo: a tendência não é só "deixar o modelo mais inteligente", é "dar ao agente formas mais seguras e controladas de alcançar os sistemas reais com que um desenvolvedor de fato trabalha" — redes internas, repositórios privados, toolchains customizadas. A distinção entre "onde o código executa" e "onde o modelo roda" também é um bom modelo mental pra manter em geral ao avaliar as alegações de privacidade de qualquer ferramenta de IA pra desenvolvimento: sempre pergunte de qual lado dessa linha um recurso específico realmente está resolvendo.
