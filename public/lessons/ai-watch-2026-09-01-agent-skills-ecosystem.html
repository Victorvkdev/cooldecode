Skills became AI's universal plug — and almost nobody checks what's inside

In under a year, "Agent Skills" went from a single Claude feature to a standard running across ~40 platforms and millions of published packages. The distribution problem is solved. The trust problem just started.

1. What is an "agent skill", exactly

An agent skill is a folder with a SKILL.md file inside — plain markdown instructions, plus optional scripts and reference files — that teaches an AI agent how to do one specific job well and consistently. Think of it as a small, reusable "how-to" that the model reads only when it needs it, instead of a wall of instructions the model has to hold in its head at all times.

The mechanism that makes this cheap is called progressive disclosure: the agent first sees only the skill's name and a one-line description. If a task matches, it then loads the full instructions. A library of hundreds of skills barely costs any context, because 99% of them stay unopened at any given moment.

Anthropic introduced Agent Skills in October 2025, then did something it had already done once before with the Model Context Protocol (MCP): it gave the format away. On December 18, 2025, the specification was published as an open standard at agentskills.io, so any vendor could build support for it without asking permission.

2. Why this spread so fast

MCP solved how an agent connects to a tool. Skills solve how an agent learns a procedure. They are complementary layers, not competitors — and because the format is "just markdown in folders", it was trivial for other companies to adopt.

The result: as of mid-2026, agent skills are portable across roughly 40 products on the official showcase, including OpenAI Codex, GitHub Copilot, Cursor, Gemini CLI, VS Code, and several open-source coding agents. A skill written once for Claude Code can run, unmodified, inside a competitor's tool — which is the clearest sign a format has stopped being one vendor's feature and become shared infrastructure.

Scale followed immediately. Community catalogs now index staggering numbers: one directory alone (SkillsMP) lists close to 1.9 million public skills scraped from GitHub, and over 2,500 Claude Code plugin marketplaces are registered on a single tracking site — ranging from polished, maintained collections to abandoned repos nobody updates anymore.

3. The marketplace landscape

Not all skill sources work the same way. The trade-off is consistent everywhere: the bigger and more open a catalog is, the less anyone has actually reviewed what's in it.

SourceRough catalog sizeWho reviews it

The pattern to notice: discovery is a solved problem in 2026 — there are more skills than anyone could ever need. Judgment about which ones are safe and good is not solved at all, and it's now the actual bottleneck.

4. The uncomfortable number: 6.2 out of 12

The first peer-reviewed benchmark of this ecosystem — SkillsBench, built by researchers from Stanford, CMU, Berkeley, and Oxford — tested how much skills actually help, across 84 tasks, 11 domains, and over 7,000 trajectories. Two numbers from that study matter more than any hype:

  • Curated, well-built skills raised task pass rates by an average of 16.2 percentage points — in regulated, expertise-heavy domains like healthcare, the gain reached 51.9 points. Skills genuinely work when they're good.
  • The average quality of publicly available skills was just 6.2 out of 12, after scoring 47,150 real public skills. The benchmark's own tests only used the top quartile (9+), because most of what's out there isn't good enough to help.

Security compounds the problem. A separate audit of over 22,000 skills found more than 140,000 issues combined — roughly 6 per skill — and dedicated research into prompt injection found it present in 36% of tested skills. A skill isn't just instructions; it can also bundle scripts that execute with real permissions. An unreviewed skill is an unreviewed dependency with code-execution rights, in exactly the same sense as an unreviewed npm package.

5. Skills vs. subagents vs. hooks — a distinction worth having straight

These three terms get mixed up constantly, and they answer different questions:

  • Skills answer "what should the agent know how to do" — a reusable procedure defined in SKILL.md.
  • Subagents answer "who does the work" — a separate worker context spawned to handle a sub-task, often in isolation from the main conversation.
  • Hooks answer "when does something happen" — event handlers that fire automatically at specific points (before a tool runs, after it finishes, and so on).

Put simply: skills are what gets called, subagents are who calls it, and hooks are what fires around the whole thing.

6. What this means in practice

If you install a community skill or plugin — whether from a Claude Code marketplace, a general skills directory, or an MCP server catalog — open the SKILL.md and any bundled scripts before running it, the same way you'd review an unfamiliar package before adding it to a project. Curation beats catalog size every time; a smaller, reviewed set of skills will outperform a giant unaudited one.

The ecosystem's own trajectory points the same way: the next phase of competition isn't about who has more skills, it's about who can prove theirs are safe. Security scanning, quality scores, and clearer governance of the open standard are what separates a directory worth trusting from one that's just a pile of markdown files with a search bar on top.

1. O que é, de fato, um "agent skill"

Um agent skill é uma pasta com um arquivo SKILL.md dentro — instruções em markdown puro, mais scripts e arquivos de referência opcionais — que ensina um agente de IA a fazer um trabalho específico bem e de forma consistente. Pense nisso como um "manual de instruções" pequeno e reutilizável que o modelo só lê quando precisa, em vez de uma parede de instruções que ele teria que carregar na cabeça o tempo todo.

O mecanismo que torna isso barato se chama progressive disclosure (divulgação progressiva): o agente primeiro vê só o nome do skill e uma descrição de uma linha. Se uma tarefa combina com aquilo, aí sim ele carrega as instruções completas. Uma biblioteca com centenas de skills quase não custa contexto nenhum, porque 99% deles ficam fechados a qualquer momento.

A Anthropic introduziu os Agent Skills em outubro de 2025 e, em seguida, fez algo que já tinha feito uma vez com o Model Context Protocol (MCP): abriu mão do formato. Em 18 de dezembro de 2025, a especificação foi publicada como padrão aberto em agentskills.io, permitindo que qualquer empresa construísse suporte a ele sem pedir permissão.

2. Por que isso se espalhou tão rápido

O MCP resolveu como um agente se conecta a uma ferramenta. Os skills resolvem como um agente aprende um procedimento. São camadas complementares, não concorrentes — e como o formato é "só markdown em pastas", foi trivial pra outras empresas adotarem.

O resultado: em meados de 2026, os agent skills já são portáveis entre aproximadamente 40 produtos na vitrine oficial, incluindo OpenAI Codex, GitHub Copilot, Cursor, Gemini CLI, VS Code e vários agentes de código open source. Um skill escrito uma vez pro Claude Code roda, sem modificação nenhuma, dentro da ferramenta de um concorrente — o sinal mais claro de que um formato deixou de ser feature de uma empresa e virou infraestrutura compartilhada.

A escala acompanhou de perto. Catálogos comunitários hoje indexam números impressionantes: só um diretório (SkillsMP) lista perto de 1,9 milhão de skills públicos raspados do GitHub, e mais de 2.500 marketplaces de plugins do Claude Code estão registrados num único site de monitoramento — indo de coleções bem cuidadas e mantidas até repositórios abandonados que ninguém mais atualiza.

3. O panorama dos marketplaces

Nem toda fonte de skill funciona do mesmo jeito. O trade-off se repete em todo lugar: quanto maior e mais aberto o catálogo, menos alguém de fato revisou o que tem dentro dele.

Padrão pra notar: em 2026, descoberta é um problema resolvido — existem mais skills do que qualquer um vai precisar. Julgamento sobre quais são seguros e bons não está resolvido de jeito nenhum, e virou o gargalo real.

4. O número desconfortável: 6,2 de 12

O primeiro benchmark revisado por pares desse ecossistema — o SkillsBench, feito por pesquisadores de Stanford, CMU, Berkeley e Oxford — testou o quanto skills realmente ajudam, em 84 tarefas, 11 domínios e mais de 7.000 trajetórias. Dois números desse estudo importam mais que qualquer hype:

  • Skills curados e bem construídos elevaram a taxa de sucesso das tarefas em 16,2 pontos percentuais, em média — em domínios regulados e exigentes como saúde, o ganho chegou a 51,9 pontos. Skills funcionam de verdade quando são bons.
  • A qualidade média dos skills disponíveis publicamente foi de apenas 6,2 de 12, depois de pontuar 47.150 skills públicos reais. Os próprios testes do benchmark usaram só o quartil superior (9+), porque a maior parte do que existe por aí não é boa o suficiente pra ajudar.

Segurança agrava o problema. Uma auditoria separada em mais de 22 mil skills encontrou mais de 140 mil problemas somados — cerca de 6 por skill — e uma pesquisa dedicada a prompt injection encontrou o problema em 36% dos skills testados. Um skill não é só instrução; ele também pode empacotar scripts que executam com permissões reais. Um skill não revisado é uma dependência não revisada com direito a executar código, exatamente no mesmo sentido que um pacote npm não revisado.

5. Skills vs. subagents vs. hooks — uma distinção que vale ter clara

Esses três termos se confundem o tempo todo, e cada um responde uma pergunta diferente:

  • Skills respondem "o que o agente deveria saber fazer" — um procedimento reutilizável definido no SKILL.md.
  • Subagents respondem "quem faz o trabalho" — um contexto de trabalho separado, disparado pra lidar com uma subtarefa, muitas vezes isolado da conversa principal.
  • Hooks respondem "quando algo acontece" — manipuladores de evento que disparam automaticamente em pontos específicos (antes de uma ferramenta rodar, depois que ela termina, e por aí vai).

Resumindo: skill é o que é chamado, subagent é quem chama, e hook é o que dispara em volta de tudo isso.

6. O que isso significa na prática

Se você instala um skill ou plugin da comunidade — seja de um marketplace do Claude Code, um diretório geral de skills, ou um catálogo de servidores MCP — abra o SKILL.md e qualquer script empacotado antes de rodar, do mesmo jeito que você revisaria um pacote desconhecido antes de adicionar num projeto. Curadoria vence tamanho de catálogo sempre; um conjunto menor e revisado de skills supera um catálogo gigante e não auditado.

A trajetória do próprio ecossistema aponta na mesma direção: a próxima fase da competição não é sobre quem tem mais skills, é sobre quem consegue provar que os seus são seguros. Verificação de segurança, notas de qualidade e uma governança mais clara do padrão aberto são o que separa um diretório confiável de uma pilha de arquivos markdown com uma barra de busca em cima.
